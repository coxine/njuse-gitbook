# 2026-复习提纲

## 云计算概念

* 云计算定义：云计算是一种模型，旨在实现对可配置计算资源共享池（如网络、服务器、存储、应用程序和服务）的普遍可用、便捷获取和按需网络访问

### 云计算的特征

* 按需自助服务：用户通过自助界面，自动获取资源
* 广泛的网络访问：资源可通过标准网络协议被访问
* 资源池化：多用户共享物理资源，逻辑隔离
* 快速弹性：资源根据负载快速伸缩
* 可计量服务：自动监控资源使用，按量计费
* 可恢复性：冗余备份与故障自动修复

### 云计算的部署模型

* 公有云：第三方提供，可公共访问
* 私有云：单一组织内部使用
* 社区云：限定特定用户社区访问
* 混合云：两种以上部署模型组合
* 扩展：边缘云、分布式云、专属云

### 云计算的服务模型

* IaaS：基础设施即服务，提供虚拟化计算资源
* PaaS：平台即服务，提供用户程序的开发和运行环境
* SaaS：软件即服务，提供用户使用的应用程序
* 新兴：CaaS（容器即服务）、FaaS（函数即服务）、DBaaS（数据库即服务）、AIaaS（AI 即服务）

### 云计算的三元认知论

* 商业模式：全新的服务交付方式
* 计算范式：云体（计算+存储+通信）+ 云栈（IaaS/PaaS/SaaS）
* 实现方式：数据中心 + 云平台管理系统（SDDC）

### 云计算的开源方法论（略）

## 云计算架构

### 微服务架构

* 将庞大单一应用拆分为多个职责单一、高度自治的小服务
* 通过服务实现组件化，按业务能力划分，去中心化，基础设施自动化

### 云计算的逻辑架构

* 云栈（云平台）：在云上建造的运行环境，支持应用发布、运行、监控、调度、伸缩
* 云体：云计算的物质基础，云计算使用的资源集合（网络、服务器、存储等）
* 云计算：利用云体和云栈进行的计算处理

## 分布式计算、存储

* 分布式计算定义：多台通过网络互联的计算机传递数据，实现信息共享，协作共同完成一个处理任务

### CAP 理论

* 一个分布式系统最多同时满足其中两项
  * 一致性 （C）：所有节点同一时间数据完全一致
  * 可用性 （A）：服务一直可用，在正常响应时间内返回信息
  * 分区容错性 （P）：遇到网络分区故障，节点间无法通信，仍能对外服务
* 多数互联网应用选 AP，保证最终一致性

### 一致性 HASH 算法

* 普通 Hash 算法的痛点：基于 Cache 数量取模，Cache 数量变化时大量数据需要重新映射
* 核心思想
  * 不再引入服务器数量 $N$，将整个 Hash 值空间组织成一个虚拟的圆环（通常是 $0$ 到 $2^{32}-1$）。
  * 同等概念：服务器（Cache）和数据（Key）都进行 Hash 计算，并映射到这个环上的某个位置。
  * 映射规则：一个 Key 沿着顺时针方向在环上寻找，遇到的第一台服务器，就是它要存储的目的地。
* 性质
  * 单调性：新增缓冲时，原有内容要么保留，要么映射到新缓冲，不会影响已有的机器
  * 平衡性：使用虚拟节点，使哈希结果尽可能分布到所有缓冲
  * 分散性：同一个内容对应同一个 Cache
  * 平滑性：机器的增减对数据搬迁（迁移）的影响是成正比的、平缓的，不会出现断崖式暴跌或暴涨

### Hadoop MapReduce 思想

* 核心：移动计算比移动数据更划算
* Map 阶段：各节点本地计算，处理本地数据
* Shuffle 阶段：洗牌，按 Key 重新分区汇总
* Reduce 阶段：汇总合并结果

### Spark RDD 思想

* RDD（弹性分布式数据集）要解决的问题
  * Hadoop MapReduce 对迭代式算法（图算法、机器学习）支持效率不高，中间结果反复读写磁盘
  * 交互式数据挖掘需反复查询同一数据子集，磁盘 I/O 成为瓶颈
* RDD 定义：容错的、并行的、只读的、可持久化的逻辑数据结构，高度受限的共享内存模型
* 五大特性：分区列表、依赖列表、计算函数、分区器、优先位置

### Hadoop 和 Spark 生态

* Hadoop：HDFS（存储） + Yarn（资源管理） + MapReduce（计算） + ZK（协调）
* Hadoop 上层：Hbase（数据库）、Hive（数仓）、Pig（脚本）、Flume（数据采集）
* Spark：Spark SQL（交互查询） + Streaming（流处理） + MLlib（机器学习） + GraphX（图计算）

### 区块链概念

* 共享的、不可篡改的分布式账本，记录交易或事件
* 区块：区块链中的基本单位，包含交易数据和元数据
* 链：区块按时间顺序连接形成链式结构，每一个区块包含前区块的哈希值，确保数据不可篡改
* 特点：去中心化、共识机制（PoW/PoS）、不可篡改、透明、智能合约
* 缺点：存储和计算开销大

## 虚拟化技术

### 第一类和第二类硬件虚拟化

* Type 1（裸机虚拟化）：Hypervisor 直接运行在硬件上
* Type 2（寄居虚拟化）：Hypervisor 运行在宿主机 OS 上

### 三种硬件级虚拟化方式

* 基于软件的完全虚拟化：解释执行/二进制翻译
* 基于硬件辅助的虚拟化：硬件加入虚拟化支持（VMCS 结构、EPT 扩展页表）
* 改操作系统的类虚拟化：修改客户 OS 内核，替换敏感指令为超级调用

### 操作系统级虚拟化

* 在主机 OS 中插入虚拟化层，同一内核运行多个虚拟机（容器）

### VMware、Xen、KVM

* VMware：VMware vSphere 裸机运行，VMware Workstation 寄居运行
* Xen：剑桥大学开源 VMM，支持半虚拟化和完全虚拟化，可实时迁移
* KVM：Linux 内核模块 （kvm.ko），利用内核能力实现 VMM，需硬件辅助

## 容器技术

### 虚拟机 vs. 容器

* 虚拟机：模拟物理基础设施，操作系统级别的资源隔离
* 容器：轻量级的虚拟化技术，模拟操作系统，进程级别的资源隔离，快速启动，资源占用低，镜像小

### Namespace、Cgroup

* Namespace：隔离资源视图，让进程"看不到"彼此（PID/User/Mount/UTS/Network/IPC）
* Cgroup：限制资源用量，控制进程"用多少"（CPU/内存/I/O）
* Namespace 侧重环境隔离，Cgroup 侧重资源管控

### Docker，Docker 镜像

* Docker：容器引擎，核心组件 Daemon、Client、Registry
* 镜像：只读容器模板，通过 Dockerfile 构建，包含文件系统、库、配置
* 镜像特点：不可修改、分层存储、版本控制（Tag）

### Docker 镜像的分层存储结构、写时复制机制《重点》

* 分层存储：镜像由多个只读 Layer 组成，不同镜像可共享相同层
* 写时复制 （COW）：容器启动时在镜像层之上添加可写容器层
* 修改文件时，将原文件从下层复制到容器层再修改，底层不变

### K8S

* 开源容器编排平台，自动化部署、扩缩和管理容器化应用
* 核心思想：声明式，持续将当前状态驱动到预期状态
* Pod：最小可部署单元，一组容器，共享 namespace、cgroup、网络、存储卷

## 云计算网络、云数据中心

### 软件定义网络的概念

* SDN 核心思想：控制转发分离架构 + 可编程性
* 利用 OpenFlow 协议，将路由器的路由过程从传输过程中分离，改以软件方式实现，集中化管理分散在各个网络设备上的控制平面

### Openflow、SDN、Overlay、P4、完全可编程网络的发展历程

* OpenFlow（2008）：将 Switch 控制权上交集中控制器
* SDN（2009）：控制转发分离，软件定义网络行为
* Overlay：在物理网络上叠加虚拟网络，支持 VM 灵活迁移
* P4（2014）：协议无关、目标无关、现场可重配置的交换芯片编程语言
* 完全可编程网络 （2020-2030）：软硬件融合，网卡、交换机、协议栈均可编程

### 数据中心节能

* 配电系统节能
* 空调系统节能
* 集装箱数据中心节能
* 管理系统节能策略和算法
* 新能源应用

### 数据中心容灾

* 备份：避免数据丢失
* 容灾：避免业务中断
* RPO（数据恢复点目标）：能容忍的数据丢失量
* RTO（恢复时间目标）：能容忍的业务停止最长时间
* 数据级容灾：保证数据完整，但服务中断
* 应用级容灾：提供不间断应用服务
* 关键技术：镜像、快照（写时复制 COW）、IP SAN 远程复制、数据库复制

## Openstack

### Openstack 的定义

* 开源云计算平台，可控制整个数据中心的计算、存储和网络资源池
* 云计算系统的控制面，自身不提供虚拟化技术，调用多种技术实现资源池管理

### 核心组件及功能

* Keystone：身份认证与服务目录
* Nova：计算资源管理，虚拟机全生命周期管理
* Glance：镜像管理服务，存储与查询操作系统镜像
* 存储
  * Swift：对象存储服务，分布式扁平的命名空间存储
  * Cinder：块存储服务，管理卷、卷快照、卷备份
* 网络
  * Neutron：网络服务，虚拟网络、路由、防火墙、负载均衡

### 以虚拟机创建为例，不同组件之间的协作

* 用户通过 Horizon 或 CLI 发起创建虚拟机请求
* Keystone 认证身份并颁发令牌
* Nova-api 接收请求，Nova-scheduler 选择最佳计算节点
* Nova-compute 通过 Glance 获取镜像，通过 Neutron 配置网络
* 通过 Cinder 挂载块存储卷
* Hypervisor 启动虚拟机实例

## 云计算安全

* 数据存储与计算安全问题：数据存储在第三方云端引发新隐患
  * 需高频高效访问、成本可动态调整、高度可信的存储计算环境
  * 阿里云等大规模公有云故障：证明多地域混合云策略的必要性
* 虚拟化安全问题：虚拟机/容器逃逸攻击
* 网络安全问题：公有云对公网暴露时存在安全问题
* 访问控制安全问题：多租户间隔离被打破

## 云原生

* 定义：一种构建和运行应用程序的理念和方法，充分利用云计算模型优势，使应用在动态、弹性的云环境中最大化发挥业务价值

### 云原生四大核心内容以及对应的落地技术

* 微服务：拆分单体为独立小服务（Spring Cloud / Dubbo）
* DevOps：开发运维一体化，促进沟通协作与整合
* 持续交付：CI/CD 流水线，代码提交到生产部署全流程自动化
* 容器：Docker 容器化 + Kubernetes 编排（敏捷基础设施）

### 微服务的概念、优势、挑战

* 概念：将大型应用拆分为多个职责单一、松耦合、可独立部署的小服务
* 优势：独立部署、故障隔离、技术栈灵活、弹性伸缩、团队自治
* 挑战：分布式复杂性、服务治理、跨服务事务一致性、接口契约管理

### DevOps

* 开发（Dev）与运维（Ops）一体化，促进部门间沟通、协作与整合
* 通过工具链和流程优化，实现应用全生命周期管理和高效交付
* 自动化所有操作，减少人工参与，加速产品交付速度

### 持续交付

* 持续集成：代码提交自动触发构建与自动化测试
* 持续部署：代码变更完成后自动分发至测试/生产环境
* 持续发布：打造可随时上线发布的软件交付能力
* 目标：将变更直接部署到生产环境

### 传统 ERP 系统转型云原生《重点》

* 传统问题：单体高度耦合、部署周期长、故障影响大、技术栈陈旧
* 改造路线：微服务拆分（按业务域解耦）→容器化（Docker 打包）→K8s 编排→Service Mesh 治理→DevOps/CI/CD
* 转型三阶段：试点期 3-6 月（非核心业务）、推广期 6-12 月（核心业务）、深化优化 1-2 年
* 三位一体保障：稳定性工程（熔断降级灰度）+可观测性（监控日志追踪）+安全体系（DevSecOps）
